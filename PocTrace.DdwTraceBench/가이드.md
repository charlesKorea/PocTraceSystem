# PocTrace.DdwTraceBench

SVDI 시험용 도구다. 설비 Tag 하나를 받아 DDW `tb_*`에서 그 설비의 모든 POC로부터 배관을 따라가고, 지나간 id와 table을 Excel로 남긴다. 설계 근거는 `docs/DDW_Trace_Flow_KO.md`다. PocTrace.Core와 라이선스 DLL을 쓰지 않는 독립 프로그램이다.

## 쓰는 법

1. `UI 폴더`에 PocTrace.UI가 실행되는 폴더를 넣는다. `PocTrace.Viewer.exe.config`와 그 옆 `config\db.secret`을 다른 exe와 같은 방식으로 읽는다. 기본 연결 이름은 `SourceDb`다. `FrmConnectionString`, `PocTraceDB`가 있으면 목록에서 고른다. 서버, 로그인, 암호를 다시 치지 않는다. 암호는 이 프로그램 설정 파일에 저장하지 않는다.
2. Linked server `remote_monami`와 카탈로그 `monami`는 기본값이다. DDW DB가 그 연결의 같은 SQL Server 안에 있으면 Linked server를 비운다. 그러면 `[monami].[dbo].tb_*`로 읽는다.
3. `연결·스키마 확인`을 먼저 누른다. 로그에는 서버, DB, 인증 종류만 나오고 암호는 나오지 않는다. 필요한 열이 있는지, Tag 속성 owner가 몇 개인지도 나온다. 열 이름이 다르면 여기서 오류 메시지가 나온다. 앞 300자만 회신한다.
4. `설비 Tag`에 Tag를 넣고(기본 `rme010n03`) `추적 실행`을 누른다. Excel은 `저장 폴더`에 `ddw-trace-{Tag}-{시각}.xlsx`로 저장된다.

## 추적 규칙

- 모든 조회는 `version_sequence < 1000000000`이다. 삭제 행은 읽지 않는다.
- Tag는 `tb_attributes`에서 `attribute_nm = 'tag'`, 값 열 = Tag로 찾는다. 값 열 이름은 `attribute_val`이나 `attribute_value` 중 있는 쪽을 쓴다.
- 시작 설비의 모든 POC(`tb_pocinstances.owner_instance_id = 설비 id`)가 출발점이다. 설비 POC 하나만 따라가지 않는다.
- POC의 `connected_poc_id`가 건너편 POC다. 건너온 POC와 이미 지난 POC로는 가지 않는다.
- 건너편 POC의 `poc_template_id`가 0이면 그 소유 객체를 `tb_pipeinstances`에서 찾는다. 길이는 `length2`(mm)가 기준이고 `length1`은 예비 열에 같이 담는다. 구경은 `pipesize_id`를 `tb_pipesize.pipesize_nm`에 맞춘다.
- 0이 아니면 `tb_modelinstances`와 `tb_modeltemplates`에서 찾는다. 찾지 못하면 반대 테이블로도 한 번 찾아 본다.
- 다음에 닿으면 이름을 기록하고 그 가지를 멈춘다.
  - `modeltemplates.bim_yn = 1`인 객체.
  - 다른 설비. 설비 판정은 `model_type`, `family_key`, `bim_yn = 0` 중 하나만 만족하면 설비다. 화면의 체크박스로 켜고 끈다.
  - 노즐로 멈추는 경우는 둘이다. `model_type`이 `50856202`이거나, 객체 이름에 `노즐`이 있고 `bim_yn = 1`인 경우다. 이름에 nozzle만 있는 damper는 노즐이 아니다. `model_type` 51382287 damper가 우선이다.
  - `model_type` 51382287이거나 이름에 damper가 있는 객체와 연결된 배관의 `pipe_type`이 `17301768`이면 Takeoff로 멈추고 그 배관 너머는 따라가지 않는다. damper만 있고 그 배관이 아니면 통과한다. damper `model_type`은 노즐 이름보다 먼저 본다.
- Takeoff는 객체가 아니라 POC다. damper가 출발 소유인 행의 connected poc id가 Takeoff이고, tag, connectiontag, hookup number는 그 POC id를 `tb_attributes.owner_id`로 읽는다.
- 노즐로 끝난 도착 행의 속성 owner는 노즐 POC가 아니라 노즐 객체의 id다. tag는 `attribute_nm = tag`, connectiontag는 `ConnectionTag`, hookup number는 `S5_LATERAL_NUMBER`다. Takeoff 행도 같은 세 이름이다.
- id는 DB의 `0x` 값과, `CONVERT(uniqueidentifier, ...)` 로 본 DDW UI id를 나눠 적는다. 추적 시트는 DB id 열을 한데 모으고 DDW id 열을 한데 모은다.
- `model_template_id`가 있는 객체는 `tb_modeltemplates`의 `division_id`, `subdivision_1_id`, `subdivision_2_id`를 적는다. 이 세 열은 GUID 문자열이라 `TRY_CAST(열 AS uniqueidentifier)`로 DDW id를 만들고, 그 값을 `CONVERT(varbinary(16), ...)`한 것이 DB id다. 글자는 `tb_division`에서 `TRY_CAST(division_id AS uniqueidentifier)`가 같은 행의 `division_value`다. 추적 시트에는 DB id, DDW id, 글자를 모두 적는다.
- `model_type` 51380485(connector_pipe)는 설비 판정에서 빼고 통과한다. 화면의 `통과 model_type`에서 바꾼다.
- `bim_yn = 0` 판정은 기본 꺼짐이다. 켜면 2차 설계 객체(밸브, 피팅 포함)가 거의 다 설비가 되어 첫 컴포넌트에서 추적이 멈출 수 있다. 시험 결과를 보고 켠다.
- `modeltemplates`를 읽을 때마다 `model_type`을 적는다. 뜻을 아는 값만 옆에 붙인다. `50594049` 설비 후보, `51380485` connector, `51380481` valve, `50856202` nozzle, `51380484` clamp, `50856201` flange, `51382287` damper, `50856193` elbow, `50857988` reducer.
- 배관의 `pipe_type`도 적는다. `17301768`은 Takeoff, `17301760`은 standard, `17301771`은 bending이다. 그 밖은 숫자만 적는다. 도착 객체가 배관이면 도착 객체 이름에 그 뜻을 적는다.

## Excel 시트

| 시트 | 내용 |
|---|---|
| 요약 | 입력, 규칙, 한도, 스키마 메모, 설비별 배관 수와 길이 합, 종료 객체 이름. 아래에 설비 POC별 `length2` 합 |
| Tag조회 | `tb_attributes`에서 찾은 owner. `tb_modelinstances` 유무, 세 판정 결과, 추적 여부 |
| 추적 | 출발 POC에서 이어진 순서(a → b → c)로 한 행씩. DB id 열과 DDW id 열을 나눠 모은다. 도착 POC owner type 열은 없다. 도착이 배관이면 이름은 pipe_type 뜻이다. `Status`는 `noz`, `tof`, `ing`, `emp`, `eqp`. Takeoff 행은 damper가 출발 소유이고 connected poc가 Takeoff POC다. 노즐 도착 행의 속성 owner는 노즐 객체 id다. division, subdivision_1, subdivision_2는 DB id, DDW id, 글자를 적는다. 출발 소유 db id 칸은 배관 짙은 하늘색, 컴포넌트 짙은 노랑, 설비·종료 옅은 빨강 |
| 배관 | 지나간 배관. `pipe_type`과 아는 의미, `length2`, `length1`, `pipesize_id`, `pipesize_nm`, `last_update` |
| 객체 | 컴포넌트와 종료 객체. 인스턴스 `model_type`과 `modeltemplates.model_type`, `family_key`, `bim_yn`, 판정 결과를 기록해 다수 데이터로 유추할 수 있게 한다 |
| POC | 본 POC 전부. `poc_template_nm`, `equipment_yn`, `memo`, `owner_type`, `connection_order` |

Excel에는 id 전체가 들어간다. 회신에는 앞 10자와 숫자 열만 쓴다. Tag 원문도 쓰지 않는다.

## 회신

회신은 `Q=TRACE`, `분=`, 요약 시트 전체와 `추적` 시트의 비고 열(복사 가능한 만큼)이다. 오류는 로그의 앞 300자다.

## 빌드

`PocTrace.DdwTraceBench.csproj`는 .NET Framework 4.8 WinForms다. NuGet은 `EPPlus 7.2.1`, `Costura.Fody 6.0.0`이다(기존 DeletedPipeLength와 같다). Release로 빌드하면 EPPlus가 exe 안에 들어가 exe 하나로 옮길 수 있다. 서버 접속은 `System.Data.SqlClient`(프레임워크 내장)이다.
