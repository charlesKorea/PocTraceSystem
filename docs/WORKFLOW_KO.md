# 작업 반영 방식

2026-11-12 담당자 지시. 별도 요청이 없는 한 아래가 기본이다.

## 기본: 코드나 문서를 고치면 main에 반영한다

1. 작업 브랜치(`cursor/<이름>-8bf6`)에서 고치고 커밋한다.
2. 검증할 수 있는 것은 검증한다(컴파일, 합성 데이터 시험). 검증하지 못한 것은 요약에 그대로 적는다.
3. 작업 브랜치를 push하고 PR을 만든다(또는 갱신한다).
4. 이어서 main에 반영한다. 별도 승인을 다시 묻지 않는다. 방법은 `git push origin HEAD:main`이고 fast-forward로 들어갈 때만 한다. main이 앞서 있으면 먼저 `git fetch origin main`으로 받아 합친 뒤 한다.
5. 강제 push, 이력 고쳐 쓰기는 하지 않는다.

## 예외

- 사용자가 "main에 반영하지 마라", "PR만", "검토 후"처럼 따로 말하면 그 말을 따른다.
- 결과를 볼 수 없는 고위험 변경(운영 DB에 쓰기, 캐시 형식 변경 등)은 반영 전에 요약에 위험을 적는다.

## 기록

- 이 방식은 `docs/README.md` 색인과 `.cursor/rules/git-workflow.mdc`에도 적혀 있다. 바꾸려면 세 곳을 같이 고친다.
- 변경 내용과 확인하지 못한 것은 PR 본문과 해당 `docs/*.md`에 남긴다.
