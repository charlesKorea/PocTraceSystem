# PocTrace System 변경 (2026-10)

실행 위치와 배포 DLL, DB 비밀번호의 현재 기준은 `SVDI-SHARED-RUN.md`다. Admin은 `D:\PocAdmin`이 맞다. UI·철거·노즐은 같은 공유 폴더에서 같은 `PocTrace.Core.dll`과 같은 캐시를 본다. 아래 본문에서 `JLic.Core.dll`을 폴더에 복사하라는 문장과 `C:\ProgramData`에 비밀번호를 둔다는 문장은 그 문서가 대체한다.

## 삭제 배관 길이 — 건설코드 Delete

입력은 기존과 같이 EQPID 엑셀이다. `PocTrace.DeletedPipeLength`가 두 경우를 삭제 설비로 본다.

- `OperationType = 2` 이고 기준일 이후인 완전 삭제
- `OperationType = 1` 인데 건설코드에 `Delete`(대소문자 무관)가 있는 설비. 5D에는 아직 남아 있다

두 번째 경우는 남아 있는 배관(OperationType 2 미만)의 길이 합과, 경로상 피팅을 이름·QCode별 수량으로 낸다. 수량은 인스턴스 기준 1회이고, 피팅 인스턴스 목록은 쓰지 않는다. 완전 삭제 설비의 피팅수는 비워 둔다. 엑셀 시트는 `요약`, `BOM`, `배관`, `미매칭`이다. 공유 캐시 쿼리는 건설코드 Delete 설비를 빼므로 이 검수는 캐시가 아니라 DB를 읽는다.

`PocTrace.DeletedPipeLength.exe`만 바꾸고 예전 `PocTrace.Core.dll`을 그대로 두면 `Int32 PocTrace.Core.Engine.DeletedPipe...` 메서드를 찾지 못한다. 공유 폴더의 DLL은 그 빌드 Web Release의 `PocTrace.Core.dll` 하나다. JLic와 Serilog는 exe 안에 있다. 폴더에 남은 예전 DLL은 지운다. DLL이 빠지거나 빌드가 다르면 창 없이 끝나고, exe 폴더의 `log\DeletedPipeLength-startup.log`에 예외가 남는다. 화면 로그는 `%LocalAppData%\PocTrace\DeletedPipeLength\logs\deleted-pipe-날짜.txt`에도 남고, exe 옆 `deleted-pipe-log.path.txt`에 그 경로가 있다.

DB 비밀번호는 공유 실행 폴더의 `config\db.secret`에만 암호화한다. SchemaKind, 캐시 경로 같은 나머지 설정은 exe.config 평문이다. 개인 C:와 `C:\ProgramData`에는 두지 않는다. exe.config에 비밀번호가 있으면 실행이 암호 파일로 옮기고 평문을 지운다.

누가 exe를 켜 두었는지는 LocalAppData가 아니라 exe 폴더의 `log\{프로그램}.log`와 `log\open\`에 남는다. 라이선스 사용자, Windows 사용자, 컴퓨터, pid가 OPEN / LICENSE / CLOSE로 기록된다. `log\open\`에 파일이 있으면 그 프로세스가 아직 파일을 잡고 있다.

## 0. 캐시 로드 메모리 (Viewer OOM)

Admin이 만든 최신 캐시를 Viewer가 읽을 때, 하단 `Initializing Graph...` 에서 `System.OutOfMemoryException` 이 날 수 있습니다. 작업 관리자 물리 메모리 %는 낮아도 발생합니다. 캐시 파일 형식과 폴더 구조는 바꾸지 않았습니다.

원인: 캐시를 이미 읽은 뒤 노드 사전 여러 개와 역인덱스를, 원본 리스트가 살아있는 동안 한 번에 만듭니다. Viewer Release는 32비트로 떠서 프로세스 주소가 약 2~4GB에서 끊깁니다. 예외 직후 Serilog가 로그 한 줄을 못 만들어 기록이 비었습니다.

`AllowDatabaseFallback` 은 이 단계와 무관합니다. 캐시 파일 읽기가 실패할 때만 쓰이며, Viewer/Web/철거/노즐은 `false` 를 유지합니다. true로 바꿔도 그래프 초기화 메모리는 줄지 않습니다.

| 항목 | 내용 |
|---|---|
| 진단 로그 | `%LocalAppData%\PocTrace\{Viewer\|Web\|Demolition\|NozzleTrace\|Admin}\logs\memory-load.log`. exe 옆 `memory-load.path.txt` 에 경로 |
| 볼 값 | 마지막 `stage=`. `procBits=32` 이고 `availVirtualMB` 가 작으면 32비트 한도. `availPageMB` 가 0이면 페이지 파일. 둘 다 남으면 배열 2GB 한도 |
| 빌드 | Viewer / Web / 철거 / 노즐 Release는 x64. Admin Release는 원래 x64. `gcAllowVeryLargeObjects` 를 exe.config에 추가 |
| 읽기 순서 | 사전을 만든 뒤 원본 리스트 참조를 놓고 역인덱스를 만든다. Admin은 역인덱스를 만들지 않는 기존 동작을 유지 |

배포 시 exe, `PocTrace.Core.dll`, `*.exe.config` 를 같이 교체합니다.

Viewer는 그대로 두고, 같은 캐시를 읽는 **로컬 웹**을 추가했습니다. 이어서 라이선스 검증을 Viewer / Web / 철거 / 노즐 / Admin에 같은 방식으로 넣었습니다.

이미 `main`에 들어간 웹 작업: PR #7~#11  
이번에 같이 `main`에 넣는 라이선스 연동: PR #12, #13 (`cursor/license-crypto-dll-49bd`)

실행 방법은 `PocTrace.Web/README.md`, 배포 경로는 `SVDI_XDrive_Manual_Deploy_KO.md`, 라이선스 절차는 `라이센스 코드/1. Latest Source Code/docs/` 를 보세요.

## 1. PocTrace.Web (Viewer와 병행)

`PocTrace.Web.exe` 는 Viewer를 끄지 않습니다. 사용자마다 한 번 실행하고, 그 세션의 브라우저만 `http://127.0.0.1:5088/` 을 엽니다. 다른 SVDI 세션에서 이 주소로 들어오지 않습니다.

| 프로그램 | 위치 | 하는 일 |
|---|---|---|
| `PocTrace.Admin.exe` | `D:\PocAdmin` | 캐시·DailyReport. 본인만 |
| `PocTrace.UI.exe` | 공용 `X:` Viewer 폴더 | 기존 WinForms Trace |
| `PocTrace.Web.exe` | 공용 `X:` **별도** Web 폴더 | 같은 캐시, 브라우저 화면 |
| `PocTrace.Demolition.exe` | 공용 또는 개인 | 철거 검수 WinForms |
| `PocTrace.NozzleTrace.exe` | 공용 또는 개인 | 노즐 역추적 WinForms |

캐시는 `X:\jHOOK\PocTraceData` 를 읽기만 합니다. Excel은 `%LOCALAPPDATA%\PocTraceWeb\jobs\` 에 둡니다. `AllowDatabaseFallback` 은 `false` 로 두고 DB 비밀번호는 넣지 않습니다.

화면 탭 세 개. 한 프로세스에서 작업은 하나만 돕니다.

- **배관 Trace:** 라인 캐시 시각, 48시간 초과 시 거절, 단건/배치, 설비 요약, Excel
- **철거검수:** Excel 업로드 또는 `Site,공정,건설코드,EQPID` 붙여넣기. 검증 그리드, 노란 오류 행 제외, 진행률, 취소, 종합 표, Excel/HTML
- **노즐추적:** BIM / Instance / GUID. 기존 노즐 exe와 같은 역추적 후 Excel

한·중 전환은 오른쪽 위. 선택은 그 브라우저에 남습니다.

아직 없는 것: 배관 Trace·노즐추적 작업 취소, 여러 사람이 캐시 한 벌을 나눠 쓰는 서버.

## 2. 라이선스 검증 (JLic.Core)

모든 PocTrace exe가 `PocTrace.Core.Licensing.PocTraceLicense` 를 통해 `LicenseApi.VerifyAnyApp(["PT","AL"])` 를 호출합니다. 실패하면 폼·웹을 열지 않습니다.

| 프로그램 | 실패 시 | 추가 제한 |
|---|---|---|
| Viewer | 시작 차단 | 배관 Trace |
| Web | 시작 차단 (종료 코드 2) | `GET /api/license`. `2차`면 철거·노즐 탭 숨김, API 403 |
| Demolition | 시작 차단 | `2차` 차단 |
| NozzleTrace | 시작 차단 | `2차` 차단 |
| Admin | 시작 차단 | Admin 그룹만 |

AccessApps에 `PT` 또는 기존 `AL` 이 있으면 통과합니다. 권한 `2차` 는 배관 Trace만 됩니다. 웹에서 탭을 숨겨도 `/api/demolition*`, `/api/nozzle-traces` 는 서버가 403으로 막습니다.

공유 실행 폴더에 꼭 같이 둡니다. `JLic.Core.dll`은 exe 안에 있으므로 폴더에 복사하지 않습니다. 남아 있으면 지웁니다.

```
Lic\jlab.lic
```

발급기(`JLicManager.exe`)와 `Keys\issuer.keys` 는 SVDI 공용 폴더에 두지 않습니다.

## 3. 배포에서 바뀐 점

1. 공유 실행 폴더에 `Lic\jlab.lic` 를 둔다. `JLic.Core.dll`은 복사하지 않는다
2. Web은 Viewer 폴더를 덮어쓰지 않고 `X:\jHOOK\Apps\PocTrace\Web\` 처럼 따로 둠. `wwwroot` 와 `UtMapping.csv` 도 같이
3. `jlab.lic` 은 관리 PC의 `JLicManager` 로만 만듦. Python 설치 불필요
4. 구형 TripleDES 라이선스 파일은 통하지 않음. 재발급 필요
